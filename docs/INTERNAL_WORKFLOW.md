## 🔄 上下游对接流程

### 工作流程图

```
[1. 本地开发]
      ↓
[2. 开发仓库 PR]
      ↓
[3. 内部测试] ✓
      ↓
[4. 转移到保密仓库] ←── 关键步骤
      ↓
[5. 上游审核]
      ↓
[6. 反馈修改] ←─┐
      ↓         │
[7. 再次审核]  │
      ↓         │
      └─────────┘
      ↓
[8. 合并到上游]
      ↓
[9. 同步回开发仓库]
```

### 详细步骤

#### 阶段 1：开发仓库工作（当前阶段）

**步骤 1.1：创建开发分支**
```bash
# 在开发仓库
git checkout -b feature/optimization-xxx
```

**步骤 1.2：开发和测试**
- 编写代码
- 本地测试
- 提交到开发分支

**步骤 1.3：创建 PR**
- 在开发仓库创建 PR
- 内部审查
- 所有测试通过

**当前状态**：✅ 已完成
- PR: `copilot/optimize-cli-performance`
- 测试：全部通过
- 准备转移

#### 阶段 2：转移到保密仓库（下一步）

**步骤 2.1：准备转移清单**
```
□ 确认所有代码已提交
□ 所有测试通过
□ 文档齐全
□ 无敏感信息
□ 无临时文件
□ 代码已经过内部审查
```

**步骤 2.2：创建保密仓库（如果尚未创建）**
```bash
# 选项 A：创建新的私有仓库
gh repo create [org]/cli-review --private

# 选项 B：使用现有私有仓库
# [提供仓库名称]
```

**步骤 2.3：转移分支**
```bash
# 添加保密仓库为远程
git remote add private [私有仓库 URL]

# 推送分支到保密仓库
git push private copilot/optimize-cli-performance

# 在保密仓库创建 PR
```

**步骤 2.4：通知上游审核人员**
- 发送审核请求
- 提供必要的上下文
- 说明改动的目的和范围

#### 阶段 3：上游审核过程

**步骤 3.1：等待初步反馈**
- 上游审核人员查看 PR
- 可能提出问题或建议
- 记录所有反馈

**步骤 3.2：响应反馈**
```bash
# 在开发仓库修改
git checkout copilot/optimize-cli-performance
# 修改代码
git commit -m "Address review feedback"

# 同步到保密仓库
git push private copilot/optimize-cli-performance
```

**步骤 3.3：迭代审核**
- 重复步骤 3.1 和 3.2
- 直到所有问题解决
- 获得批准

#### 阶段 4：合并到上游

**步骤 4.1：最终确认**
```
□ 所有审核意见已处理
□ 所有测试通过
□ 文档已更新
□ 变更日志已更新
□ 获得批准
```

**步骤 4.2：创建上游 PR**
```bash
# Fork 官方仓库（如果还没有）
gh repo fork cli/cli

# 推送到您的 fork
git remote add upstream https://github.com/cli/cli.git
git push origin copilot/optimize-cli-performance

# 创建 PR 到官方仓库
gh pr create --repo cli/cli --base trunk --head [your-fork]:copilot/optimize-cli-performance
```

**步骤 4.3：等待官方合并**
- 官方维护者审查
- 可能有额外的反馈
- 最终合并

#### 阶段 5：善后工作

**步骤 5.1：同步回开发仓库**
```bash
# 更新本地
git fetch upstream
git checkout trunk
git merge upstream/trunk

# 推送到开发仓库
git push origin trunk
```

**步骤 5.2：清理分支**
```bash
# 删除已合并的分支
git branch -d copilot/optimize-cli-performance
git push origin --delete copilot/optimize-cli-performance
```

**步骤 5.3：更新文档**
- 记录这次贡献
- 更新内部文档
- 分享经验教训

### 在保密仓库阶段

#### 不能做的事
❌ 不在公开渠道讨论细节
❌ 不分享保密仓库链接
❌ 不在社交媒体提及
❌ 不在公开 issue 中引用

✅ 使用私有沟通渠道
✅ 记录所有重要决策
✅ 定期同步状态
✅ 遵守保密协议

### 信息分级

| 级别 | 内容 | 可公开范围 |
|------|------|-----------|
| 公开 | 一般性优化想法 | 任何人 |
| 内部 | 具体实现细节 | 开发团队 |
| 保密 | 审核中的代码 | 您 + 我 + 上游人员 |
| 机密 | 安全相关改动 | 仅授权人员 |
